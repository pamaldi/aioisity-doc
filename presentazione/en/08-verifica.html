The game

How we will test it

Feasibility first, then the comparison. Outcomes are decided before looking at the data.

  1. 1 · Feasibilitya few children, with the analyst: is the game usable and liked?
  2. 2 · Agreementdo the app data match direct observation?
  3. 3 · Comparisonthree conditions with the same game and the same materials
  4. 4 · Decisionthe engine stays only if it brings an advantage
Condition A

Manual

Settings tuned by the adult, with all the necessary accommodations.

Condition B

Simple rule

Adapts only on correct responses: a baseline close to Pickstar's approach.

Condition C

Proposed engine

Besides correct answers it looks at how the gesture goes and which prompts were present; it proposes one explained change at a time.

Outcomes decided in advance: independence in the task, interaction errors, responses on new examples, maintenance, acceptability and the child's choices, time required of the adult.

The engine becomes the default only if it beats A and B without increasing the adult's workload. If it only increases time spent in the game, the proposal must be revised.

Learned skills do not reset when moving from one condition to another: the comparison will need to control order and practice. An efficacy study would require a dedicated design.
